# Контракт обновления лора

Правила для любого, кто меняет лор энциклопедии: для человека и для будущей автоматизации,
которая следит за новостями World of Warcraft: Forever. Автоматизации пока нет. Этот документ
описывает границы, в которых ей разрешено работать.

## Инварианты

1. **Только через pull request.** Работа ведётся в отдельной ветке, и открывается PR в `main`.
   Пушить в `main` нельзя, деплоить нельзя: деплой запускает только человек, вручную
   (`.github/workflows/deploy.yml`, `workflow_dispatch`).
2. **Каждый факт — с источником.** Меняется лор → у записи есть `sourceIds`, а в
   `docs/research/evidence/` лежат дословные цитаты. `npm run verify:evidence` проходит без ошибок.
3. **Человек утверждает каждое изменение со статусом `FOREVER`, `CHANGED` или `BETA`.** PR с такими
   правками не мержится автоматически.
4. **`ESTABLISHED` молча не переписывается.** Противоречие со сложившейся историей оформляется
   одним из двух способов:
   - новым текстом со статусом `CHANGED` и записью журнала, где `supersedes` указывает на прежнюю
     запись;
   - статусом `BETA` или `UNCONFIRMED`, пока официального подтверждения нет.
5. **Year-1 fence.** Retail после первого года оригинального WoW не выдаётся за канон Forever.
   Если официальные тексты расходятся, приводятся обе версии.

## Источники

| Уровень | Что | Как использовать |
|---|---|---|
| Официальные | news.blizzard.com, worldofwarcraft.blizzard.com, blue-посты, мануалы Blizzard, текст в игре | Цитата попадает в реестр доказательств |
| Наводки | wowhead, wowpedia, Reddit, стримы, датамайн | Только чтобы найти официальный источник. Цитировать и ссылаться нельзя |

Датамайн и наблюдения на бете — это `BETA`, и только когда их подтверждает официальный текст
или внутриигровой текст с указанием билда. Иначе — `UNCONFIRMED`.

## Порядок работы

1. **Найти** новую информацию о Forever в официальных источниках.
2. **Исследовать** через Grok: веб-поиск, режим только для чтения. Извлечь дословные английские
   цитаты с URL.

   ```bash
   grok --prompt-file PROMPT.md --deny 'Write(*)' --deny 'Edit(*)' --deny 'Bash(*)' \
     --cwd <repo> --effort xhigh --output-format json
   ```

   Никогда не запускать Grok с `--debug` или `--debug-file`: лог открытым текстом дампит токены
   окружения.
3. **Записать доказательства** в `docs/research/evidence/*.json` (формат —
   `docs/research/evidence/README.md`), новый источник — в `src/content/sources/core.json`.
   Запустить `npm run verify:evidence`. Любой статус, кроме `OK` (`NOT_FOUND`,
   `LOCATOR_MISMATCH`, `FETCH_ERROR`, `UNKNOWN_SOURCE`), останавливает работу: цитату сверяют
   с живой страницей и исправляют запись, а не подгоняют проверку.
4. **Сравнить** с содержимым репозитория и выбрать статус:

   | Ситуация | Статус |
   |---|---|
   | Новое, объявлено официально для Forever | `FOREVER` |
   | Forever официально меняет то, что было в первом году оригинального WoW | `CHANGED` |
   | Видно на бете и подтверждено официальным или внутриигровым текстом | `BETA` |
   | Есть только наводка или разночтение без подтверждения | `UNCONFIRMED` |
   | Подтверждает сложившуюся историю | `ESTABLISHED` |

5. **Править минимально:** только затронутые файлы в `src/content/`. Обновить `updatedAt` и
   `sourceIds`.
6. **Дописать журналы:**
   - `src/content/changelog/entries.json` — запись для читателя (страница «Журнал обновлений»);
   - `src/content/update-log/entries.json` — машиночитаемая запись (формат ниже).
7. **Проверить:** `npm test`, `npm run build`, `npm run test:e2e`. Смотреть на код возврата,
   а не на вывод, пропущенный через grep.
8. **Закоммитить** в ветку с префиксом `lore:` и открыть PR. В описании PR: что изменилось,
   какой статус, ссылки на источники и список записей реестра.
9. **Уведомить** человека, только если изменение значимое: новая сущность, смена статуса,
   новая или сдвинутая дата. Опечатки и переформулировки без новых фактов уведомлений не стоят.

## Журнал изменений лора

Файл `src/content/update-log/entries.json`, схема `updateLogEntrySchema` в `src/lib/content.ts`,
тест `tests/update-log.test.ts`.

```json
{
  "id": "2026-11-04-launch-date",
  "date": "2026-11-04",
  "entityIds": ["forever/announced-schedule"],
  "status": "FOREVER",
  "summary": "Что изменилось, одной-двумя фразами по-русски.",
  "sourceIds": ["forever-hub"],
  "supersedes": "2026-09-17-forever-announcements-baseline",
  "commitSha": "8fe3edb"
}
```

- `id` — `ГГГГ-ММ-ДД-slug`, начинается с `date`. Записи идут по возрастанию даты.
- `entityIds` — ссылки вида `collection/id` на существующие записи: `chapters`, `characters`,
  `factions`, `locations`, `forever`, `timeline`, `glossary`.
- `sourceIds` — ID из `src/content/sources/core.json`. Пустым может быть только у `ESTABLISHED`.
- `supersedes` — ID более ранней записи журнала, которую эта запись заменяет.
- `commitSha` — необязателен. В коммите с самой правкой хэш ещё неизвестен, поэтому его
  дописывают отдельным коммитом или не указывают.
- **Журнал только дополняется.** Старые записи не редактируются и не удаляются. Ошибку
  исправляет новая запись с `supersedes`.

Две первые записи — отправные точки: проверенные главы после аудита и сравнения Forever по
анонсам BlizzCon 2026. На них ссылаются будущие записи с `supersedes`.

## Проверка источников по расписанию

`.github/workflows/evidence.yml` раз в неделю прогоняет `npm run verify:evidence`. Падение
значит, что официальная страница изменилась, переехала или исчезла. Разбирает человек или
автоматизация по этому контракту, через PR. Автоматически реестр не правится.
